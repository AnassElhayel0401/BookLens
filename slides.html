Contexte & objectifs

BookLens — un explorateur de livres utilisant la base Open Library (40M+ de livres).

3 objectifs principaux :

  1. Chercher des livres (par titre, auteur ou mot-clé)
  2. Consulter la fiche détaillée (couverture, note, description)
  3. Sauvegarder ses favoris dans une bibliothèque personnelle

HTML5 CSS3 JS vanilla fetch() localStorage

Séparation des responsabilités :

  • api.js : couche d'accès aux données (partagée par les 3 pages) + icônes SVG, thème, favoris
  • 1 fichier JS par page = 1 contrôleur
  • CSS unique avec variables (:root) pour les 2 thèmes

  • Tendances du jour affichées à l'arrivée sur le site

Zoom technique : Structure HTML

Balises principales utilisées :

<header>Barre de navigation
<main>Contenu principal
<section>Bloc logique (résultats, détail…)
<form>Formulaire de recherche
<input>Champ texte + sélecteur
<button>Actions (rechercher, favoris)
<img>Couvertures des livres
<a href>Liens entre pages

Organisation :

  • 3 pages HTML = 3 vues distinctes
  • 1 fichier CSS commun (variables pour les thèmes)
  • 4 fichiers JS (1 par page + 1 partagé)

Zoom technique : CSS & JavaScript

CSS

  • Variables CSS : :root { --couleur: valeur }
  • Grille responsive : display: grid
  • Mode sombre : on change les variables avec [data-theme="dark"]
  • Media queries : adapter au mobile

JavaScript

  • fetch(url) : appeler une API sans recharger
  • async/await : attendre la réponse
  • DOM : document.getElementById(), innerHTML
  • localStorage : sauvegarder les favoris dans le navigateur
  • addEventListener : réagir aux clics

Design & responsive

  • Palette chaude « bibliothèque » : bois, cuir, papier crème
  • Mode sombre via variables CSS et [data-theme], sans flash au chargement
  • Icônes SVG inline (style Lucide) — aucune dépendance externe
  • Grille responsive : grid-template-columns: repeat(auto-fill, minmax(180px, 1fr))
  • Media queries pour mobile (formulaire, fiche détail en colonne)
  • Micro-interactions : survol des cartes, transitions, spinner

Conclusion

  • Toutes les fonctionnalités demandées, sans framework ni backend
  • Code modulaire et commenté, réutilisable
  • Allers-retours API maîtrisés (asynchrone, erreurs, cache)
