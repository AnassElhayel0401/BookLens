1. Introduction et objectifs

BookLens est un explorateur de livres développé dans le cadre du cours Applications Web. L'application permet de rechercher des livres parmi les millions de références de l'Open Library (projet de l'Internet Archive), de consulter leur fiche détaillée et de se constituer une bibliothèque personnelle.

Le cahier des charges imposait les contraintes techniques suivantes :

  • HTML5, CSS3 et JavaScript vanilla uniquement (aucun framework type React ou Vue) ;
  • appels à l'API en AJAX (ici via fetch() et async/await) ;
  • aucun backend : l'application tourne entièrement côté client ;
  • persistance des favoris dans le localStorage du navigateur ;
  • design responsive et moderne.

2. Architecture de l'application

L'application est composée de trois pages HTML, d'une feuille de style unique et de quatre fichiers JavaScript. La structure suit un principe simple : un fichier JS par page (le « contrôleur » de la page), plus un module commun api.js chargé sur les trois pages. 

BookLens/
├── index.html          page principale : recherche + grille de résultats
├── book.html           fiche détaillée d'un livre
├── bookshelf.html      bibliothèque personnelle (favoris)
├── slides.html         présentation reveal.js
├── rapport.html        ce rapport
├── css/
│   └── style.css       styles, thèmes clair/sombre, responsive
└── js/
    ├── api.js          appels Open Library + favoris + icônes + thème
    ├── app.js          logique de index.html
    ├── book.js         logique de book.html
    └── bookshelf.js    logique de bookshelf.html

Le module api.js joue le rôle de couche d'accès aux données : il centralise tous les appels réseau (searchBooks, getWorkDetails, getWorkRating, getAuthor, getTrendingBooks, getCoverUrl) ainsi que les utilitaires partagés : gestion des favoris en localStorage, génération d'icônes SVG, bascule de thème et échappement HTML. Cette factorisation évite toute duplication entre les trois pages.

3. L'API Open Library

Open Library expose une API REST publique, gratuite et sans clé d'authentification, qui renvoie des données au format JSON. Les endpoints utilisés sont :

UsageEndpointChamps exploités
Recherche GET /search.json?q|title|author=…&limit=20&page=…&sort=… key, title, author_name, first_publish_year, cover_i, ratings_average, number_of_pages_median, numFound
Tendances du jour GET /trending/daily.json mêmes champs que la recherche
Détail d'une œuvre GET /works/{id}.json title, description, subjects, covers, authors
Note moyenne GET /works/{id}/ratings.json summary.average
Auteur GET /authors/{id}.json name
Couvertures covers.openlibrary.org/b/id/{cover_id}-M|L.jpg image M (grille) ou L (fiche détail)

Exemple d'appel AJAX avec fetch() et gestion d'erreur :

async function searchBooks(query, type = "q", limit = 20, page = 1, sort = "") {
    const param = ["title", "author"].includes(type) ? type : "q";
    let url = `${OL_BASE}/search.json?${param}=${encodeURIComponent(query)}`
            + `&limit=${limit}&page=${page}`;
    if (sort) url += `&sort=${sort}`;

    const response = await fetch(url);
    if (!response.ok) {
        throw new Error(`Erreur API Open Library (${response.status})`);
    }
    const data = await response.json();
    return { docs: data.docs || [], numFound: data.numFound || 0 };
}

4. Fonctionnalités réalisées

4.1 Page de recherche (index.html)

  • Recherche générale, par titre ou par auteur (sélecteur de type) ;
  • Tendances du jour affichées à l'arrivée sur le site ;
  • Tri des résultats : pertinence, plus récents, plus anciens, mieux notés ;
  • Pagination « Charger plus » (20 résultats par page) avec compteur total ;
  • grille de cartes : couverture, titre, auteur, année, note moyenne ;
  • bouton cœur sur chaque carte : ajout/retrait des favoris sans quitter la grille ;
  • placeholder stylisé en CSS lorsque le livre n'a pas de couverture ;
  • états de chargement (spinner), d'erreur réseau et de résultat vide ;
  • recherche pilotable par l'URL (index.html?q=fantasy), utilisée par les tags de sujets.

4.2 Fiche détaillée (book.html)

  • couverture haute définition, titre, auteur(s), année de première publication ;
  • description complète et note moyenne affichée en étoiles ;
  • nombre de pages (médiane) lorsque disponible ;
  • sujets et genres cliquables : un clic relance une recherche sur ce sujet ;
  • bouton « Ajouter à ma bibliothèque » / « Dans ma bibliothèque » ;
  • lien externe vers la fiche officielle Open Library.

4.3 Bibliothèque personnelle (bookshelf.html)

  • liste de tous les livres sauvegardés, persistée en localStorage ;
  • statut de lecture par livre : À lire, En cours, Lu, avec pastille colorée sur la couverture ;
  • onglets de filtrage par statut et champ de recherche interne (titre/auteur) ;
  • suppression d'un livre de la bibliothèque ;
  • compteur de favoris visible dans la barre de navigation de toutes les pages.

4.4 Fonctionnalités transverses

  • Mode sombre persistant, appliqué avant le rendu pour éviter tout flash ;
  • icônes SVG inline (style Lucide) générées par une fonction utilitaire, sans aucune dépendance externe.

5. Choix d'implémentation

5.1 Persistance avec localStorage

Les favoris sont stockés sous la clé booklens_favorites sous forme d'un tableau JSON sérialisé. Chaque favori est un objet {id, title, author, year, cover, status, addedAt} : 

function addFavorite(book) {
    const favorites = getFavorites();
    if (!favorites.some((b) => b.id === book.id)) {
        favorites.push({ status: "toread", addedAt: Date.now(), ...book });
        localStorage.setItem(FAVORITES_KEY, JSON.stringify(favorites));
    }
}

La lecture est protégée par un try/catch : si la valeur stockée est corrompue, l'application repart d'une liste vide au lieu de planter. Le thème choisi (clair/sombre) est persisté de la même manière sous la clé booklens_theme.

5.2 Transfert d'informations entre pages

L'endpoint /works/{id}.json ne renvoie ni les noms d'auteurs (seulement leurs clés), ni l'année, ni la note. Pour éviter des appels réseau superflus, la page de recherche mémorise les informations du résultat cliqué dans le sessionStorage ; la fiche détail les réutilise. Si l'utilisateur arrive par une URL directe, la page bascule sur des appels de secours (/authors/{id}.json pour les noms, /ratings.json pour la note).

5.3 Sécurité : prévention des injections XSS

Tout texte provenant de l'API (titres, auteurs, sujets…) est échappé avant insertion dans le DOM via une fonction escapeHtml() s'appuyant sur textContent : 

function escapeHtml(text) {
    const div = document.createElement("div");
    div.textContent = String(text);
    return div.innerHTML;
}

5.4 Icônes SVG sans dépendance

Plutôt que d'utiliser des emojis (rendu hétérogène selon les systèmes) ou une bibliothèque d'icônes externe, une fonction icon(name, size, filled) génère des SVG inline au trait (stroke="currentColor"), qui héritent automatiquement de la couleur du texte et s'adaptent donc aux deux thèmes.

6. Design et responsive

La direction artistique évoque une bibliothèque chaleureuse : tons bois et cuir (bruns), papier crème, accents dorés, typographie serif (Georgia). Toutes les couleurs sont déclarées en variables CSS dans :root ; le mode sombre se résume à redéfinir ces variables sous le sélecteur [data-theme="dark"] : 

:root        { --cream: #faf6ef; --paper: #fffdf8; --text: #3b2f2a; }
[data-theme="dark"] { --cream: #211a16; --paper: #2c241f; --text: #ece2d4; }

Le responsive repose sur deux mécanismes :

  • une grille fluide repeat(auto-fill, minmax(180px, 1fr)) qui adapte automatiquement le nombre de colonnes à la largeur de l'écran ;
  • une media query à 700 px qui passe la fiche détail en une colonne, élargit le formulaire de recherche et resserre la grille pour mobile.

Les micro-interactions (survol des cartes, transitions de thème, spinner de chargement, rotation du bouton de thème) renforcent le caractère moderne de l'interface sans recourir à la moindre bibliothèque JavaScript.

7. Difficultés rencontrées et solutions

DifficultéSolution mise en place
La description d'une œuvre est tantôt une chaîne, tantôt un objet {value}. Fonction extractDescription() qui normalise les deux formats.
Champs souvent absents : couverture, note, année, description, sujets. Valeurs par défaut systématiques, placeholder CSS pour les couvertures, messages « Aucune description disponible »…
/works/{id}.json ne donne pas les noms d'auteurs ni la note. Cache sessionStorage alimenté par la recherche + appels de secours /authors et /ratings.
Risque d'injection XSS via les données de l'API. Échappement systématique avec escapeHtml() avant toute insertion en innerHTML.
Flash blanc au chargement en mode sombre. Mini-script inline dans le <head> qui applique le thème avant le premier rendu.
Latence de l'API sur certaines requêtes. États de chargement visibles (spinner), pagination plutôt que chargement massif, loading="lazy" sur les images.

8. Pistes d'amélioration

  • suggestions de recherche en temps réel (autocomplétion avec debounce) ;
  • notes et commentaires personnels sur les livres de la bibliothèque ;
  • export / import de la bibliothèque au format JSON ;
  • transformation en PWA avec cache hors-ligne (Service Worker) ;
  • page dédiée aux auteurs (biographie, œuvres complètes).

9. Conclusion

BookLens remplit l'intégralité du cahier des charges — recherche AJAX, fiche détaillée, bibliothèque persistante, design responsive — et va au-delà avec le tri, la pagination, les tendances du jour, les statuts de lecture et le mode sombre. Le projet nous a permis de mettre en pratique les fondamentaux du web côté client : manipulation du DOM, programmation asynchrone (fetch, async/await, Promise.all), persistance navigateur (localStorage, sessionStorage) et CSS moderne (variables, grid, media queries), le tout sans aucune dépendance JavaScript externe.
